NNegotiable Calendar利用規約

プライバシーポリシー

制定・更新日：2026年9月23日

はたけ/Furukawa（以下「運営者」）は、Negotiable Calendar（以下「本サービス」）のデータを、以下の目的と範囲で取り扱います。本サービスは、予定の詳細を組織に公開せずに相談可能な時間帯を共有し、調整依頼と回答を管理するサービスです。

取得・利用する情報共有と委託AIの利用保存と削除問い合わせ

1. 取得・利用する情報

Googleログイン

Googleアカウントの識別子、メールアドレスと確認状態、氏名・表示名、プロフィール画像のURLを取得し、本人確認、プロフィール表示、ワークスペース内のメンバー識別に使用します。Googleのパスワードを本サービスへ入力する必要はありません。プロフィール画像はブラウザーから画像配信元へ読み込まれるため、その配信元に通信情報が送られます。

Google Calendar連携（任意）

Googleログインとカレンダー接続の許可は別です。接続に同意した場合、現在はメインカレンダーを読み取り、本人の予定表示と、相談可能な時間帯の計算に使います。Google上の予定の作成・変更・削除は行いません。

新規接続で要求する権限は calendar.events.owned.readonly（自分が所有するカレンダーの予定の読み取り）です。既存の calendar.readonly 権限での接続にも対応しています。アプリの更新だけで、以前にGoogleへ許可した権限が縮小・撤回されるわけではありません。

予定名、説明、場所、参加者、会議リンク、開始・終了日時などをGoogleから取得し、本人の画面に表示します。予定名・説明・場所・参加者・会議リンクは同期用データベースに保存しません。同期用には予定・カレンダーの識別子、開始・終了時刻、busy状態、同期位置・結果、付与された権限などを保存します。継続同期用の更新トークンは暗号化して保管します。

本サービスで入力・生成する情報

ワークスペース、所属・役割、招待、勤務時間と共有ルール、一時的な公開状態、調整依頼のタイトル・メッセージ・候補日時・回答・担当者・履歴、アプリ内通知と操作監査情報を、機能提供とアクセス制御のために保存します。利用者が依頼文に自分で書いた予定の詳細は、Google予定から分離された別の共有データです。

Cookie・通信情報・お問い合わせ

ログイン状態の維持とOAuth手続きの保護に、Cookieと期限付きのサーバー側状態を使用します。広告・行動追跡用のCookieやアクセス解析タグは設置していません。クラウド基盤では、IPアドレス、User-Agent、リクエストURL、アクセス時刻、応答結果などの通信・運用ログが記録される場合があります。お問い合わせで送られたメールアドレスや本文は、回答、本人確認、問題調査に使用します。認証コード、Cookie、秘密鍵、不要な予定詳細は送らないでください。

2. 共有範囲・委託・人による閲覧

所属と権限に応じて、ワークスペースのメンバー情報、共有ルールから作った相談可能性などの公開状態を組織内に表示します。公開状態にGoogleの予定名・説明・参加者・場所は含めません。調整依頼・回答・担当引継ぎの情報は、依頼の関係者など、機能上の閲覧権限を持つ利用者に表示されます。操作監査情報にも組織の権限に応じた閲覧制限があります。

運用基盤としてGoogle Cloud（Cloud Run、Firestore、Secret Manager、Cloud Logging）とFirebase Hostingを利用します。認証・予定取得ではGoogleの認証サービスとCalendar APIに通信します。お問い合わせにはGmailを利用します。これらの提供に必要な範囲で各基盤がデータを処理します。アプリの実行とデータベースの設定先は東京リージョンですが、すべての関連処理・配信・ログが日本国内だけに限定されるとは保証しません。

Googleから取得したデータとその派生データを、広告配信、販売、信用評価、汎用AIモデルの学習のために利用・提供しません。運営者によるGoogleデータの閲覧は、特定のデータについて本人の明示同意を得た場合、セキュリティ上の調査に必要な場合、または法令上必要な場合に限定します。提供・開示も、本サービスの明示された機能を本人の同意に基づいて提供するため、セキュリティ対応のため、または法令上必要な範囲に限ります。

本サービスによるGoogle APIから取得した情報の利用および他のアプリへの転送は、Limited Useの要件を含む Google API Services User Data Policy に従います。この方針の公表は、Googleによる審査承認を意味しません。

3. AIを使う場合

現在のAI機能は、対応するChromeの端末内モデル（Gemini Nano）による既存候補の比較です。利用者が処理対象を確認し、同意して実行した場合だけ使用します。AIに渡すのは一時的な候補ID、開始・終了時刻、選択式の「早い時間／遅い時間」の希望です。予定名、説明、場所、参加者、実際の予定ID、自由入力の依頼本文は渡しません。

本サービスは、この機能の入力・出力を外部のクラウドAIへ送信せず、学習用に利用せず、AIのプロンプト・結果としてサーバーに保存しません。比較前後の候補確認には本サービスのAPIとの通信が必要です。初回にはChromeによるモデルのダウンロードが発生することがあり、通信量と端末の保存領域を使います。ブラウザー自体の通信・設定はChromeの管理対象です。

対応しない環境では通常の候補選択を使えます。外部AIへの自動切り替えはなく、AIが予約やGoogleの予定を確定・変更することもありません。将来、外部AIへの送信やデータの利用目的を変更する場合は、送信先・対象データ・利用目的・保存や学習の条件を事前に説明し、必要な新たな同意を得てから適用します。

4. 保存期間・切断・削除

プロフィール、共有ルール、調整依頼などは、サービスの利用に必要な間、保存します。一般の利用データについて一律の日数による自動削除は設定していません。認証セッションやOAuth状態には有効期限がありますが、有効期限の経過がその保存レコードの即時消去を意味するものではありません。お問い合わせメールにも固定の自動削除期限は設定していません。

  • Calendar接続解除：アカウントメニューの「Calendar接続を解除」から、保存した連携情報と同期用予定データを削除し、対応する公開状態の共有を停止できます。プロフィールや調整依頼の削除とは別の操作です。Google側の許可状況はGoogleアカウントでも確認・撤回できます。
  • アカウント削除：メニューの「アカウントを削除」から確認入力を行い、プロフィール、認証情報、所属、関連する依頼・通知・監査情報などの削除処理を開始します。共有組織の最後の管理者は、先に別の管理者を確保する必要がある場合があります。関連依頼は他の参加者の一覧からも削除されます。
  • 削除処理の制限：途中で失敗した場合はアクセスを停止し、運営者による再試行が必要です。古い処理による復活を防ぐため、旧ユーザーID・削除状態・開始時刻の最小限の記録を残します。この記録の自動削除期限は設定していません。過去の不完全な処理で残った孤立データなどは個別調査が必要な場合があり、全データの即時完全消去は保証しません。
  • 運用ログ：2026年9月23日に確認したGoogle Cloud Loggingの保存設定は、通常ログ用の _Default が30日、必須監査ログ用の _Required が400日です。アカウント削除とは別に、この保持設定に従います。アプリ内の操作監査情報とは異なります。
  • バックアップ：同日の確認で、本サービスのFirestoreデータベースはPITR（過去時点への復元）無効、定期バックアップ設定なし、東京リージョンのFirestoreバックアップ一覧は空でした。これは基盤側のすべての複製、過去の手動エクスポート、利用者が保存したコピーが存在しないことを保証するものではありません。

本人データのエクスポート機能を利用できますが、すべての内部記録を含むものではありません。開示・訂正・削除・利用停止などの相談、切断や削除が完了しない場合は、下記へご連絡ください。対象と本人確認の方法、対応可能な範囲をご案内します。Googleに保存された元の予定や、他の利用者が既に保存したコピーは、本サービス内の削除では消えません。

5. 安全管理と方針の変更

HTTPS、認証・所属に基づくアクセス制御、更新トークンの暗号化、秘密情報の管理サービスを用います。ただし、障害や漏えいのリスクが完全になくなることは保証できません。事故が判明した場合は影響を調査し、必要な対応と、法令・影響に応じた利用者への通知を行います。

変更は本ページに更新日と変更内容を掲載します。Googleデータの新たな利用・共有など、同意が必要な変更は、説明と同意取得より前に適用しません。

# Production deployment

The repository includes a Render Blueprint that creates:

- a Docker API service in Singapore;
- a static Vite Web service;
- a managed PostgreSQL database.

## First deployment

1. Open [Deploy to Render](https://render.com/deploy?repo=https://github.com/furukawa1020/Negotiable-Calender).
2. Connect the GitHub repository and select the Blueprint.
3. Enter GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET when prompted.
4. Create the resources and wait for both services to report live.
5. In Google Cloud Console, register these authorized redirect URIs:
   - https://negotiable-calendar-api-furukawa1020.onrender.com/api/v1/auth/google/callback
   - https://negotiable-calendar-api-furukawa1020.onrender.com/api/v1/calendar/google/callback
6. Add https://negotiable-calendar-furukawa1020.onrender.com as an authorized
   JavaScript origin and OAuth consent-screen application domain.

CALENDAR_TOKEN_ENCRYPTION_KEY is generated by Render and DATABASE_URL is read
from the managed database. Neither value is committed or exposed to the Web
build.

## Smoke checks

Open the Web URL, then verify the API independently:

```text
GET https://negotiable-calendar-api-furukawa1020.onrender.com/healthz
```

The health endpoint must return HTTP 200. Then sign in, connect Calendar, sync,
create an invitation, and accept it from a second Google account.

## Rollback

Use Render's deploy history to redeploy the previous successful commit. Database
schema changes in this project are additive, so the previous application remains
compatible. Do not regenerate CALENDAR_TOKEN_ENCRYPTION_KEY during rollback,
because existing Calendar grants depend on it.

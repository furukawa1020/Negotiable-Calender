# 回答・辞退・未確定依頼の取り下げ

Issue #137 は `POST /requests/{id}/async`、`/decline`、`/cancel` の本番保存処理を対象とする。会議承認・確定会議取消は既存の専用トランザクションを使う。

## 状態遷移

| 操作 | 実行者 | 遷移前 | 遷移後 |
| --- | --- | --- | --- |
| 非同期回答 | 宛先本人 | suggested、期限内 | async + 回答本文 |
| 辞退 | 宛先本人 | suggested、期限内 | declined |
| 取り下げ | 依頼者本人 | pending / suggested / delegated | cancelled |

同じ終端操作の再送は `200` と `Idempotency-Replayed: true` を返す。非同期回答は前後空白除去後の本文も一致する場合に限る。新たな送信キーは不要。既存状態が異なる場合は `409 request_resolution_conflict`、新規回答時点で期限が到来していれば `409 request_resolution_expired`。同一回答の再送は期限後でも可能。確定候補IDを持つ依頼はこの経路では取り消せない。

本番の認証ミドルウェアが指定する本人・アクティブ組織と依頼を照合する。他人・別組織には `404`、所属喪失には `403`。Firestore は両当事者・関連委譲先のアカウント削除フェンスも確認する。再送であっても権限確認を省略しない。

## 一括保存と競合

Firestore は依頼文書・所属・削除マーカーをトランザクションで読み、状態更新、相手への通知、組織監査ログを同時に確定する。Postgres は依頼行を `FOR UPDATE`、所属行を `FOR SHARE` でロックする。承認との競合も同じ依頼を更新するため、後続処理は終端状態を上書きできない。

通知・監査IDは依頼IDに基づく決定的な値。通知や監査の衝突で依頼状態もロールバックする。再送は書き込まないため、既読時刻や最初の更新時刻を戻さない。通知・監査に回答本文や依頼タイトルを複製しない。生の保存エラーもHTTP応答に出さない。

保存結果が不明な場合は `503`。同じ操作・回答文で再試行するか、一覧を再取得する。旧版で既に終端になった依頼も再送として読めるが、過去の通知欠損を修復するバックフィルは実行しない。

## 画面と検証

画面は依頼単位で同時操作を抑止し、送信中の回答編集を止める。20秒で通信を打ち切り、不明な結果を成功扱いしない。失敗時は回答文を保持する。組織・アカウント切替や画面破棄後の古い応答は反映しない。本文をローカルストレージへ保存する下書き機能はない。

状態遷移表の単体テスト、APIの再送・権限・エラー、Firestore/Postgresの並行再送、承認との4操作競合、通知・監査衝突のロールバック、期限・所属・削除制御を検証する。Playwrightは架空の認証済みユーザーと通信断を使い、同一再送と再読み込み後の表示を検証する。実Googleアカウントの受入試験とは区別する。

追加サービス・DBマイグレーションは不要。Google OAuth審査、外部カレンダーへの書込み、委譲先への引継ぎ、期限切れ一括処理はこのIssueの完了には含めない。

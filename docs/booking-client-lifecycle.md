# 予約画面のアカウント・Workspace境界 (#173)

受信・送信一覧、承認、辞退、非同期回答、未確定取消、日時変更、確定取消、
ICSダウンロードは、開始時のアカウント世代と依頼画面のWorkspace世代を保持する。
応答/JSON/Blobの解析後、通知や保存結果を反映する前に世代を照合する。
古い処理のエラーや終了処理も現在の表示・読込状態を上書きしない。

セッション復元、成功したログアウト・退会・Workspace変更・招待受諾後の
Workspace変更で依頼一覧と読込/承認状態をリセットする。切り替え前の行を
残さず、同じ組織へ戻った場合も旧処理を復活させない。App破棄時も無効になる。
操作が拒否された場合は世代を進めず、現在の予約操作を維持する。
Google Calendarの接続解除だけでは予約操作の世代を変えない。

組織切り替え後の一覧は未取得として「更新」を案内する。実際に取得した空一覧
とは区別する。同一一覧を複数回更新した場合は、最後に開始した読込だけが
応答・エラー・loading状態を反映できる。

ICSはBlob取得後にも照合し、旧処理からダウンロードを開始しない。
一時anchorはfinallyで除去し、object URLはclick失敗時も含め1秒後に解放する。
既に開始したダウンロードや送信済みのサーバ操作を取り消す仕組みではない。

修正前CIでは17件の追加回帰ケースが失敗し、既存161件と拒否された切替を
維持する3ケースは成功した。合成応答を遅延させて検証し、本番の予約変更、
アカウント削除、個人情報のダウンロード、Google認可は実行しない。

この変更はクライアント側の境界であり、サーバ認可の代替ではない。サーバの
履歴一覧がどの組織を含むかは変更しない。同一Workspace内の全更新順序や
依頼画面以外の非同期処理を一括で監査したものでもない。
